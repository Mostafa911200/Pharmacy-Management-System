# Pharmacy Management System

## Class Relationships and OOP Concepts

This project is a complete console-based Pharmacy Management System written in Python using Object-Oriented Programming.

Project structure:

```text
Pharmacy Management System
|
|-- Person
|   |-- Customer
|   `-- Supplier
|
|-- Category
|-- Medicine
|-- SaleItem
|-- Sale
`-- Pharmacy
```

OOP concepts used:

- Classes and objects: The system creates objects from `Medicine`, `Category`, `Supplier`, `Customer`, `SaleItem`, `Sale`, and `Pharmacy`.
- Constructors: Every main class uses `__init__()` to initialize object data.
- Encapsulation: Important fields such as medicine price, quantity, names, IDs, and contact data are stored in private attributes like `self.__price` and controlled through properties.
- Inheritance: `Customer` and `Supplier` inherit from the base class `Person`.
- `super().__init__()`: Child classes reuse the parent constructor to initialize shared person data.
- Polymorphism: `Customer` and `Supplier` override `display_info()`, so the same method name behaves differently depending on the object type.
- CRUD: The `Pharmacy` class manages create, read, update, and delete operations for medicines, categories, suppliers, and customers.
- Business rules: Expired medicines cannot be sold, sale quantity cannot exceed stock, prices must be positive, and inventory is updated automatically after sales.
- Reports and tracking: The system includes low-stock alerts, expiration tracking, search, filters, and a sales report.


## How to Run

```bash
python pharmacy_management_system.py
```

The program first runs a demonstration, then asks whether to open the interactive console menu.

The interactive menu supports:

- CRUD submenus for medicines, categories, suppliers and customers.
- Recording sales (the stock is deducted automatically and can never go negative).
- Searching medicines by ID, name or category (case-insensitive, partial match).
- Viewing the inventory with filters: all, available, out-of-stock, low-stock
  (quantity <= 10), stock below a custom number, active and inactive.
- Low-stock alerts and expiration tracking (expired and expiring-soon lists).
- A sales report with the number of sales, total items sold, total revenue,
  most sold medicine and full sale details.

The demonstration at startup shows, in order: adding medicines, searching,
updating, recording a sale, automatic inventory updates, low-stock detection,
expiration detection, the expired-medicine rule, the insufficient-stock rule,
polymorphism with Person references, and the sales report.


GUI version:

```bash
python pharmacy_gui.py
```

The GUI uses Tkinter and includes tabs for inventory search/filtering, medicine CRUD, category/supplier/customer management, sales, and reports.
